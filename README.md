# LoL Lore Video Pipeline

**Self-hosted:** след сценария от Claude всичко (глас, картини, видео) се изпълнява локално на вашия Mac. Без API ключове, без абонаменти, без изпращане на данни навън.

От един `script.json` до готово ~10-минутно YouTube видео (16:9), 3 вертикални Shorts (9:16), субтитри, YouTube глави с реални таймкодове, thumbnail и метаданни за качване.

```
Claude (ръчно) ─► script.json ─► глас (Kokoro) ─► картини (Flux/MLX) ─► времева линия + аудио микс ─► Ken Burns клипове
                                                                                        │
                                       metadata / thumbnail / SRT ◄── Shorts 9:16 ◄── Master 16:9
```

## 1. Изисквания

- Mac с Apple Silicon (M1 или по-нов). Тествано на M5 Pro, 48 GB.
- Памет: 16 GB минимум, 32 GB+ препоръчително.
- Диск: ~25 GB свободни (модели ~16 GB, Python среда ~1.5 GB, всеки епизод ~1.5 GB).
- Интернет само при първото пускане (теглене на моделите).
- [Homebrew](https://brew.sh).

## 2. Инсталация

**1) Системни пакети.** Трябва `ffmpeg-full`, не обикновеният `ffmpeg`: обикновената Homebrew версия вече е без libass и субтитрите тихо не се изпичат във видеото.

```bash
brew install ffmpeg-full python@3.12 espeak-ng git
brew uninstall ffmpeg 2>/dev/null; brew link --force ffmpeg-full    # ffmpeg-full става системният ffmpeg
ffmpeg -hide_banner -filters | grep -E " (subtitles|loudnorm) "      # трябва да покаже и двата реда
```

`espeak-ng` се ползва от Kokoro за думи, които не са в речника му.

**2) Кодът.**

```bash
git clone https://github.com/ikonomovdaniel2-cpu/VideoProducing.git LoL_Video_Pipeline
cd LoL_Video_Pipeline
```

(Репото е private: трябва достъп до него и вход в GitHub, например с `brew install gh && gh auth login`.)

**3) Python среда.**

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-local.txt
cp .env.example .env        # настройките по подразбиране са self-hosted, нищо не е задължително
```

**4) Модели (еднократно, автоматично).** При първото пускане се теглят от Hugging Face в `~/.cache/huggingface`:

| Какво | Размер | Нужен ли е вход |
|---|---|---|
| Kokoro-82M (глас) | ~330 MB | не |
| spaCy `en_core_web_sm` (ползва се от Kokoro, инсталира се сам във `.venv`) | ~13 MB | не |
| FLUX.2-klein-4B (картини, по подразбиране) | ~16 GB | не |

При 3–4 MB/s връзка това е около 1.5 часа. След това всичко работи и без интернет (`export HF_HUB_OFFLINE=1`, ако искате да го гарантирате).

**По желание: FLUX.1-schnell.** Вече е gated модел в Hugging Face. Ако искате да го ползвате:

1. Безплатен акаунт на https://huggingface.co/join.
2. На https://huggingface.co/black-forest-labs/FLUX.1-schnell натиснете **Agree and access repository** (одобрява се веднага).
3. Read token от https://huggingface.co/settings/tokens, после в терминала:
   ```bash
   hf auth login          # поставете токена; на "Add token as git credential?" отговорете n
   ```
4. В `.env`: `MFLUX_MODEL=schnell` (~34 GB допълнително теглене).

## 3. Всеки път преди работа

```bash
cd LoL_Video_Pipeline
source .venv/bin/activate
```

Всички команди по-долу се пускат в активираната среда.

## 4. Първи тест

```bash
python run_pipeline.py --input script.example.json --dry-run
```

Използва placeholder картини и вградения macOS глас (`say`), без да зарежда модели. Отнема под минута и проверява, че FFmpeg и целият път до готовите видеа работят. После с истинските модели (първия път тегли теглата, виж т.2):

```bash
python run_pipeline.py --input script.example.json
```

Резултатът е в `output/darius_lore_ep1/`.

## 5. Реален епизод

1. Отворете `claude_prompt.md`, заменете темата и езика, поставете в Claude.
2. Запишете отговора в `script.json` (може с ```json оградите – скриптът ги чисти). В репото има готов пример: пълен епизод за Darius.
3. Проверка без разходи (валидация + оценка на дължината):
   ```bash
   python run_pipeline.py --input script.json --check
   ```
4. Пълен рън:
   ```bash
   python run_pipeline.py --input script.json
   ```

Резултат:

```
output/<project_name>/
├── Master.mp4        # 1920x1080 @30fps, H.264 + AAC, -14 LUFS, изпечени субтитри
├── Master.srt        # качете го в YouTube Studio като субтитри (по-добро от авто-генерираните)
├── Short_01..03.mp4  # 1080x1920, заглавие отгоре, TikTok-стил субтитри с подсветка на думата
├── thumbnail.jpg     # 1280x720
├── metadata.txt      # заглавие/описание с глави/тагове – за copy-paste
├── metadata.json     # същото, машинно-четимо
└── _work/            # кеш (глас, картини, клипове)
```

**Къде се вижда прогресът:**
- в терминала: лог за всяка стъпка (`[2/6] Изображения`, `Сцена 14: изображение готово` …); `-v` за подробности;
- във Finder: `output/<project_name>/_work/images/raw/` се пълни с картини една по една;
- Activity Monitor → процесът `python`; Window → GPU History показва натоварването при картините.

**Важно за лаптоп:** затворен капак на батерия приспива Mac-а и спира рендера (продължава при събуждане, нищо не се губи). За дълги рънове дръжте капака отворен или зарядното включено.

`output/` не се качва в git (видеата са над лимита на GitHub).

## 6. Кеширане и редакции

Всеки глас, картина и клип се кешира по хеш на съдържанието си. Ако промените текста на сцена 14, при следващото пускане се генерира наново **само** гласът на сцена 14 (и картината ѝ, ако сте сменили промпта), а всичко останало се взима от кеша. Тест на 66-сценов епизод: редакция на една сцена = ~3 мин вместо ~57 мин. Прекъснат рън (Ctrl+C, мрежова грешка, заспал Mac) просто се пуска отново. `--force` игнорира кеша; `--clean` трие `_work/` след успех.

Удобен цикъл: генерирайте, прегледайте картините в `_work/images/raw/`, изтрийте файловете, които не ви харесват (или сменете `image_prompt`), пуснете отново.

## 7. CLI флагове

| Флаг | Действие |
|---|---|
| `--input`, `-i` | път до сценария (по подразбиране `script.json`) |
| `--dry-run` | placeholder картини + `say` глас, без зареждане на модели |
| `--check` | само валидация и оценка |
| `--preview "текст"` | озвучава само този текст (проба на глас и произношение) |
| `--tts kokoro\|say\|silent\|elevenlabs` | избор на глас |
| `--images mflux\|comfyui\|placeholder\|fal\|replicate` | избор на генератор |
| `--res 1080\|4k` | резолюция на мастъра |
| `--layout blur\|crop` | оформление на Shorts |
| `--music path` | фонова музика (файл или папка) с автоматично заглушаване под гласа |
| `--encoder libx264` | софтуерен енкодер вместо хардуерния |
| `--no-subs`, `--no-shorts` | изключва съответната част |
| `--force`, `--clean`, `-v` | регенерация / почистване / подробен лог |

Всяка настройка от `.env` може да се смени и само за един рън, например:

```bash
MFLUX_MODEL=schnell KOKORO_VOICE=bm_george KOKORO_LANG=b python run_pipeline.py -i script.json
```

| `SUBS_FONT` | `Arial` | шрифт на субтитрите (трябва да е инсталиран) |

## 9. Локални модели

### Глас: Kokoro
82M-параметров невронен TTS с лиценз Apache 2.0. 66 сцени се озвучават за ~1.5 мин и Kokoro връща тайминг на всяка дума, така че субтитрите съвпадат точно. Опитайте няколко гласа с `--preview` и изберете (`KOKORO_VOICE`). Kokoro поддържа английски и няколко други езика, но не и български.

### Картини: mflux
Flux модели, пренаписани за Apple MLX, работят директно на GPU-то на Mac-а, без отделен сървър. Моделът се зарежда веднъж и генерира всички сцени една след друга.

| `MFLUX_MODEL` | Лиценз | Вход в HF | Бележки |
|---|---|---|---|
| `flux2-klein-4b` **(по подразбиране)** | Apache 2.0 | не | 4 стъпки, ~48 s/картина на M5 Pro. Чете дълги промптове, затова описанията на героите се спазват най-добре. |
| `schnell` | Apache 2.0 | **да** (виж т.2) | 4 стъпки, ~56 s/картина, по-кинематографичен вид, но текстовият му енкодер чете само ~256 токена и губи детайли от описанията (в теста Darius получи брада, която я няма в описанието). |
| `dev` | **некомерсиален** (Black Forest Labs) | да | 25 стъпки, по-бавен. Прочетете лиценза, преди да го ползвате за монетизиран канал. |

### Картини: ComfyUI (за повече контрол)
Ползвайте го, ако искате SDXL, LoRA за конкретен стил, upscaler или собствен workflow.
1. Инсталирайте ComfyUI Desktop (comfy.org) и сложете модела в `ComfyUI/models/checkpoints/`.
2. Направете работещ workflow (1920x1088 за Flux, 1344x768 за SDXL).
3. В позитивния промпт напишете точно `{{PROMPT}}`, в негативния `{{NEGATIVE}}`, в seed полето `{{SEED}}`.
4. Menu → **Export (API)** → `comfyui_workflow_api.json` в папката на проекта.
5. `IMAGE_ENGINE=comfyui` (ComfyUI трябва да е стартиран).

### Облачни (по желание)
Кодът за ElevenLabs, fal.ai и Replicate остава, но се ползва само ако го изберете изрично (`--tts elevenlabs`, `--images fal`) и сложите ключ в `.env`.

## 10. Консистентни герои и произношение

### Герои
Flux не познава героите на League, а всеки кадър се генерира отделно. Без помощ Darius ще изглежда различно във всяка сцена. Затова сценарият има секция `characters`:

```json
"characters": {
  "darius": "a towering broad-shouldered warrior in his forties, short-cropped black hair with grey streaks, scarred stern face, heavy black and crimson plate armor ...",
  "darius_young": "a gaunt dark-haired boy of about ten ..."
}
```

В `image_prompt` героят се споменава като `{darius}`, а пайплайнът вмъква точно същото описание във всяка сцена. Различни възрасти или форми са отделни ключове. `--check` хваща недефинирани `{ключ}`, имена, написани без скоби (тогава описанието не се вмъква), неизползвани герои и твърде дълги промптове (важно за schnell, който чете ~256 токена).

Това дава много по-добра консистентност, но не идеална: лицата пак ще варират леко. Съветът в промпта към Claude е да предпочита силуети, кадри в гръб и детайли.

### Произношение
Речникът променя текста **само за гласа**. Субтитрите остават с правилното изписване, защото таймингите се връщат към оригиналните думи.

- `pronunciations.json`: глобален речник за всички епизоди (има стартов списък с имена като Kha'Zix, Rek'Sai, LeBlanc, Freljord...).
- `"pronunciations"` в `script.json`: за конкретния епизод, с предимство пред глобалния. Claude ги генерира по промпта.
- Стойност: фонетичен правопис с тирета (`"Kah-Zix"`) или IPA в наклонени черти (`"/kəzˈɪks/"`, само за Kokoro).
- Работи и за притежателни форми (`Kha'Zix's`) и имена от няколко думи.

Проба без да пускате целия пайплайн (пуска и звука):
```bash
python run_pipeline.py --preview "Kha'Zix hunts in the Void beneath Shurima."
python run_pipeline.py -i script.json --preview "..."   # + речника от сценария
```

`--check` показва кои записи от речника се ползват и предупреждава за имена с апостроф (тип `Xin'Zhao`), които липсват. Промяна в речника регенерира гласа само на засегнатите сцени.

## 11. Скорост

Измерено на MacBook M5 Pro, 48 GB, за епизод от 66 сцени (11:04 мин):

| Стъпка | Време |
|---|---|
| Глас (Kokoro) | ~1.5 мин |
| Картини (FLUX.2-klein, 1920x1088) | ~53 мин (~48 s/картина) |
| Аудио микс, Ken Burns клипове, мастър, Shorts | ~3 мин |
| **Общо** | **~57 мин** |
| Повторен рън след редакция на 1 сцена | ~3 мин |

Удобен работен цикъл: първо `--images placeholder` с истинския глас, за да проверите темпото и дължината; после пуснете картините.

## 12. Проблеми

| Симптом | Решение |
|---|---|
| Субтитрите не се виждат във видеото / `FFmpeg е без libass` | инсталирайте `ffmpeg-full` (т.2): обикновеният Homebrew `ffmpeg` е без libass |
| `Липсва ffmpeg` / `няма филтър` | `brew install ffmpeg-full && brew link --force ffmpeg-full` |
| `... е gated модел в Hugging Face` / 401 при теглене | `hf auth login` и приемете лиценза на модела (т.2), или `MFLUX_MODEL=flux2-klein-4b` |
| `cannot import name '_IntegralLike' from 'numbers'` | Pillow 13 е несъвместим с Python 3.12: `pip install -r requirements-local.txt` (закрепва Pillow<13) |
| Рендерът "замръзва" за час+ | Mac-ът е заспал (затворен капак на батерия). Отворете капака/включете зарядното – продължава сам |
| Видеото е ~11 мин вместо ~10 | Kokoro на `KOKORO_SPEED=0.95` говори ~136 думи/мин (оценката е за 150). Ползвайте `KOKORO_SPEED=1.0` или сценарий от ~1350 думи |
| Фалшив "подпис"/надпис в ъгъла на картина | изтрийте картината от `_work/images/raw/` и пуснете отново (генерира се наново) |
| Субтитрите са с грешен шрифт | `SUBS_FONT` трябва да е инсталиран шрифт (Font Book). Default: Arial |
| `Липсва Kokoro` / `Липсва mflux` | `pip install -r requirements-local.txt` в активирания `.venv` |
| Kokoro грешка за espeak | `brew install espeak-ng` |
| Mac-ът забавя драстично / swap | `MFLUX_QUANTIZE=4` и по-ниска `MFLUX_WIDTH/HEIGHT`, затворете други тежки програми |
| `mflux Python API несъвместимо` | не е проблем: скриптът минава автоматично на `mflux-generate` CLI |
| Short е над 60 s | YouTube приема до 3 мин; ако искате, вдигнете `SHORTS_MAX_SEC` |
| Искам друга картина за една сцена | изтрийте я от `_work/images/raw/` или сменете промпта и пуснете отново |

## 14. Какво е поправено/подобрено

Спрямо оригиналната спецификация:

- **moviepy е премахнат.** `moviepy.editor` не съществува в moviepy 2.x, а и рендерирането през Python кадър по кадър е многократно по-бавно. Всичко минава през FFmpeg.
- **Кадрово точен синхрон.** Всяка сцена е цяло число кадри, аудиото ѝ е допълнено до точно `кадри × 1600` семпъла (48 kHz / 30 fps). Гласът и картината не се разминават дори след 75 сцени. Целият разказ е един непрекъснат WAV, така че няма щракания между сцените.
- **Ken Burns без трептене.** Наивният `zoompan` „трепери“, защото закръгля координатите до цели пиксели; тук картината се супер-семплира до ~8K преди движението. Движенията се редуват (zoom in/out, pan) вместо само zoom-in.
- **Shorts не се режат от мастъра.** Shorts се сглобяват от чистите клипове на сцените, с отделни вертикални субтитри и заглавие.
- **Истински субтитри** по реалния тайминг на всяка дума (Kokoro, ElevenLabs); при `say`/`silent` се изчисляват пропорционално.
- **YouTube глави с реални таймкодове.** Claude пише `{{CHAPTERS}}`, а пайплайнът го попълва след генерирането на гласа и спазва правилата на YouTube (първа глава 0:00, всяка ≥10 s).
- **Звук по стандарт:** -14 LUFS (нивото на YouTube) и по желание фонова музика с автоматично заглушаване под гласа (sidechain).
- **Валидация преди разходи**, **retry с backoff**, **консистентни герои** и **речник за произношение**.
- **Self-hosted по подразбиране:** Kokoro за глас и Flux през MLX (или ComfyUI) за картини. Облачните услуги са само опция.

При инсталацията (октомври 2026, подробности в `DEPLOYMENT_REPORT.md`):

- **Pillow<13**: Pillow 13 чупи mflux на Python 3.12.
- **mflux 0.23**: поддръжка на новото API (иначе моделът се презарежда за всяка сцена).
- **Силата на звука** вече реално е -14 LUFS (еднопасовият loudnorm оставаше на ~-15.5).
- **Ясна грешка при gated модели** + нова опция `MFLUX_MODEL=flux2-klein-4b`, която стана основният модел.
- **ffmpeg-full** вместо slim `ffmpeg` (заради субтитрите).

**Планирано:** истинско видео с движение вместо Ken Burns (локален image-to-video модел, LTX-2.5) – в процес на оценка.
