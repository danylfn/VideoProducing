# LoL Lore Video Pipeline

**Self-hosted:** след сценария от Claude всичко (глас, картини, видео) се изпълнява локално на вашия Mac. Без API ключове, без абонаменти, без изпращане на данни навън.

От един `script.json` до готово 10-минутно YouTube видео (16:9), 3 вертикални Shorts (9:16), субтитри, YouTube глави с реални таймкодове, thumbnail и метаданни за качване.

```
Claude (ръчно) ─► script.json ─► глас ─► картини ─► времева линия + аудио микс ─► Ken Burns клипове
                                                                        │
                       metadata / thumbnail / SRT ◄── Shorts 9:16 ◄── Master 16:9
```

## 1. Инсталация (macOS, Apple Silicon)

```bash
brew install ffmpeg python@3.12 espeak-ng
cd ~/LoL_Video_Pipeline
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-local.txt
cp .env.example .env        # по подразбиране вече е self-hosted, нищо не е задължително за попълване
```

Homebrew версията на FFmpeg има всичко нужно (libass за субтитри, `h264_videotoolbox`). `espeak-ng` се ползва от Kokoro за думи, които не са в речника му.

**Еднократно изтегляне на теглата.** При първото пускане Kokoro (~330 MB) и Flux schnell (~24 GB в пълна точност, кешира се в `~/.cache/huggingface`) се теглят от Hugging Face. Това е само веднъж. След това работи и без интернет; ако искате да го гарантирате, добавете `export HF_HUB_OFFLINE=1` в терминала.

**Памет.** Flux е голям модел. С 8-bit квантизация (по подразбиране) е подходящ за Mac с 32 GB+ unified memory. При 16–24 GB сложете `MFLUX_QUANTIZE=4` и евентуално `MFLUX_WIDTH=1344`, `MFLUX_HEIGHT=768` (скриптът увеличава картината до 1080p), или минете на SDXL през ComfyUI (т.6).

## 2. Първо: безплатен тест

```bash
python3 run_pipeline.py --input script.example.json --dry-run
```

Използва placeholder картини и вградения macOS глас (`say`), без да зарежда модели. Отнема минута-две и проверява, че FFmpeg и целият път до готовите видеа работят. После опитайте с истинските модели на същия кратък пример:

```bash
python3 run_pipeline.py --input script.example.json
``` Резултатът е в `output/darius_lore_ep1/`.

## 3. Реален епизод

1. Отворете `claude_prompt.md`, заменете темата и езика, поставете в Claude.
2. Запишете отговора в `script.json` (може с ```json оградите – скриптът ги чисти).
3. Проверка без разходи (валидация + оценка на дължината и броя символи за TTS):
   ```bash
   python3 run_pipeline.py --input script.json --check
   ```
4. Пълен рън:
   ```bash
   python3 run_pipeline.py --input script.json
   ```

Резултат:

```
output/<project_name>/
├── Master.mp4        # 1920x1080 @30fps, H.264 + AAC 192k, -14 LUFS, изпечени субтитри
├── Master.srt        # качете го в YouTube Studio като субтитри (по-добро от авто-генерираните)
├── Short_01..03.mp4  # 1080x1920, заглавие отгоре, TikTok-стил субтитри с подсветка на думата
├── thumbnail.jpg     # 1280x720
├── metadata.txt      # заглавия/описания/тагове – за copy-paste
├── metadata.json     # същото, машинно-четимо (за бъдеща автоматизация на качването)
└── _work/            # кеш (глас, картини, клипове)
```

## 4. Кеширане и редакции

Всеки глас, картина и клип се кешира по хеш на съдържанието си. Ако промените текста на сцена 14, при следващото пускане се генерира наново **само** гласът на сцена 14 (и картината ѝ, ако сте сменили промпта), а всичко останало се взима от кеша. Прекъснат рън (Ctrl+C, мрежова грешка) просто се пуска отново. `--force` игнорира кеша; `--clean` трие `_work/` след успех.

Удобен цикъл: генерирайте, прегледайте картините в `_work/images/`, изтрийте файловете, които не ви харесват (или сменете `image_prompt`), пуснете отново.

## 5. CLI флагове

| Флаг | Действие |
|---|---|
| `--dry-run` | placeholder картини + `say` глас, без зареждане на модели |
| `--check` | само валидация и оценка |
| `--preview "текст"` | озвучава само този текст (проба на глас и произношение) |
| `--tts kokoro\|say\|silent\|elevenlabs` | избор на глас |
| `--images mflux\|comfyui\|placeholder\|fal\|replicate` | избор на генератор |
| `--res 1080\|4k` | резолюция на мастъра |
| `--layout blur\|crop` | оформление на Shorts |
| `--music path` | фонова музика (файл или папка) с автоматично заглушаване под гласа |
| `--encoder libx264` | софтуерен енкодер вместо хардуерния |
| `--no-subs`, `--no-shorts` | изключва съответната част |
| `--force`, `--clean`, `-v` | регенерация / почистване / подробен лог |

## 6. Локални модели

### Глас: Kokoro
82M-параметров невронен TTS с лиценз Apache 2.0. Работи на CPU достатъчно бързо (10-минутен разказ за няколко минути) и връща тайминг на всяка дума, така че субтитрите съвпадат точно. Опитайте няколко гласа на кратък пример и изберете (`KOKORO_VOICE`): за епичен разказ добре стоят `am_michael`, `am_fenrir`, `bm_george` (за британските `bm_*` сложете `KOKORO_LANG=b`). Kokoro поддържа английски и няколко други езика, но не и български.

### Картини: mflux (по подразбиране)
Flux, пренаписан за Apple MLX, работи директно на GPU-то на Mac-а, без отделен сървър. Моделът се зарежда веднъж и генерира всички сцени една след друга.
- `MFLUX_MODEL=schnell`: 4 стъпки, бърз, лиценз Apache 2.0, без въпроси за монетизация.
- `MFLUX_MODEL=dev`: 25 стъпки, по-добро качество, но теглата са с некомерсиален лиценз на Black Forest Labs. Прочетете го, преди да го ползвате за монетизиран канал. Изисква и `huggingface-cli login` + приемане на лиценза в страницата на модела.

### Картини: ComfyUI (за повече контрол)
Ползвайте го, ако искате SDXL, LoRA за конкретен стил, upscaler или собствен workflow.
1. Инсталирайте ComfyUI Desktop (comfy.org) и сложете модела в `ComfyUI/models/checkpoints/`.
2. Направете работещ workflow (1920x1088 за Flux, 1344x768 за SDXL).
3. В позитивния промпт напишете точно `{{PROMPT}}`, в негативния `{{NEGATIVE}}`, в seed полето `{{SEED}}`.
4. Menu → **Export (API)** → `comfyui_workflow_api.json` в папката на проекта.
5. `IMAGE_ENGINE=comfyui` (ComfyUI трябва да е стартиран).

Единството на стила идва от `STYLE_SUFFIX`, който се добавя към всеки промпт. Променете го в `.env`, за да смените визията на целия канал.

### Облачни (по желание)
Кодът за ElevenLabs, fal.ai и Replicate остава, но се ползва само ако го изберете изрично (`--tts elevenlabs`, `--images fal`) и сложите ключ в `.env`.

## 6.5 Консистентни герои и произношение

### Герои
Flux не познава героите на League, а всеки кадър се генерира отделно. Без помощ Darius ще изглежда различно във всяка сцена. Затова сценарият има секция `characters`:

```json
"characters": {
  "darius": "a towering broad-shouldered warrior in his forties, short-cropped black hair with grey streaks, scarred stern face, heavy black and crimson plate armor ...",
  "darius_young": "a gaunt dark-haired boy of about ten ..."
}
```

В `image_prompt` героят се споменава като `{darius}`, а пайплайнът вмъква точно същото описание във всяка сцена. Различни възрасти или форми са отделни ключове. `--check` хваща недефинирани `{ключ}`, имена, написани без скоби (тогава описанието не се вмъква), неизползвани герои и промптове, които са твърде дълги за Flux schnell (той чете около 256 токена; ако промптът е по-дълъг, стилът в края се губи).

Това дава много по-добра консистентност, но не идеална: лицата пак ще варират леко. Съветът в промпта към Claude е да предпочита силуети, кадри в гръб и детайли. За пълна консистентност следващата стъпка е ComfyUI с IP-Adapter или LoRA.

### Произношение
Речникът променя текста **само за гласа**. Субтитрите остават с правилното изписване, защото таймингите се връщат към оригиналните думи.

- `pronunciations.json`: глобален речник за всички епизоди (има стартов списък с имена като Kha'Zix, Rek'Sai, LeBlanc, Freljord...).
- `"pronunciations"` в `script.json`: за конкретния епизод, с предимство пред глобалния. Claude ги генерира по промпта.
- Стойност: фонетичен правопис с тирета (`"Kah-Zix"`) или IPA в наклонени черти (`"/kəzˈɪks/"`, само за Kokoro).
- Работи и за притежателни форми (`Kha'Zix's`) и имена от няколко думи.

Проба без да пускате целия пайплайн (на Mac се пуска и звукът):
```bash
python3 run_pipeline.py --preview "Kha'Zix hunts in the Void beneath Shurima."
python3 run_pipeline.py -i script.json --preview "..."   # + речника от сценария
```

`--check` показва кои записи от речника се ползват и предупреждава за имена с апостроф (тип `Xin'Zhao`), които липсват. Промяна в речника регенерира гласа само на засегнатите сцени.

## 7. Какво е поправено/подобрено спрямо оригиналната спецификация

- **moviepy е премахнат.** `moviepy.editor` не съществува в moviepy 2.x, а и рендерирането през Python кадър по кадър е многократно по-бавно. Всичко минава през FFmpeg.
- **Кадрово точен синхрон.** Всяка сцена е цяло число кадри, аудиото ѝ е допълнено до точно `кадри × 1600` семпъла (48 kHz / 30 fps). Гласът и картината не се разминават дори след 75 сцени. Целият разказ е един непрекъснат WAV, така че няма щракания между сцените.
- **Ken Burns без трептене.** Наивният `zoompan` „трепери“, защото закръгля координатите до цели пиксели; тук картината се супер-семплира до ~8K преди движението. Движенията се редуват (zoom in/out, pan) вместо само zoom-in.
- **Shorts не се режат от мастъра.** Рязането без прекодиране става само по keyframe-и (неточно), а мастърът вече има хоризонтални субтитри. Shorts се сглобяват от чистите клипове на сцените, с отделни вертикални субтитри и заглавие.
- **Истински субтитри.** ElevenLabs `/with-timestamps` дава времето на всяка дума, така че субтитрите съвпадат точно с гласа (при `say`/`silent` се изчисляват пропорционално).
- **YouTube глави с реални таймкодове.** Claude не може да знае таймкодовете предварително, затова пише `{{CHAPTERS}}`, а пайплайнът го попълва след генерирането на гласа и спазва правилата на YouTube (първа глава 0:00, всяка ≥10 s).
- **Звук по стандарт:** loudnorm до -14 LUFS (нивото на YouTube) и по желание фонова музика с автоматично заглушаване под гласа (sidechain).
- **Контекст между сцените в ElevenLabs** (`previous_text`/`next_text`) за естествена интонация на прехода.
- **Валидация преди разходи:** невалиден JSON, липсващи полета, грешни диапазони на Shorts, твърде дълго заглавие или скрипт, който няма да излезе ~10 мин, се хващат преди първата платена заявка.
- **Retry с backoff** при 429/5xx и мрежови грешки.
- **Консистентни герои** (`characters` + `{ключ}` в промптовете) и **речник за произношение** (само за гласа, субтитрите остават правилни).
- **Self-hosted по подразбиране:** Kokoro за глас и Flux през MLX (или ComfyUI) за картини. Облачните услуги са само опция.
- Дребни корекции: Whisper е за разпознаване на реч, не за синтез (премахнат от TTS опциите).

## 8. Скорост

Най-бавната част са картините: 60–75 сцени с Flux на Mac отнемат от десетки минути до около час и повече, в зависимост от модела, стъпките, резолюцията и паметта. Пуснете го и оставете машината да работи. Гласът (Kokoro) и рендерът на видеото (FFmpeg + хардуерен енкодер) са в рамките на минути. Благодарение на кеша при корекции се преправя само промененото.

Удобен работен цикъл: първо `--images placeholder` с истинския глас, за да проверите темпото и дължината; после пуснете картините.

## 9. Проблеми

| Симптом | Решение |
|---|---|
| `Липсва ffmpeg` / `няма филтър` | `brew install ffmpeg` (или `brew reinstall ffmpeg`) |
| Субтитрите са с грешен шрифт | `SUBS_FONT` трябва да е инсталиран шрифт (Font Book). Default: Arial |
| `Липсва Kokoro` / `Липсва mflux` | `pip install -r requirements-local.txt` в активирания `.venv` |
| Kokoro грешка за espeak | `brew install espeak-ng` |
| Mac-ът забавя драстично / swap | `MFLUX_QUANTIZE=4` и по-ниска `MFLUX_WIDTH/HEIGHT`, затворете други тежки програми |
| `mflux Python API несъвместимо` | не е проблем: скриптът минава автоматично на `mflux-generate` CLI |
| Flux dev: 401/403 при изтегляне | `huggingface-cli login` и приемете лиценза на модела в Hugging Face |
| Short е над 60 s | YouTube приема до 3 мин; TikTok и повече. Ако искате повече, вдигнете `SHORTS_MAX_SEC` |
| Искам друга картина за една сцена | изтрийте я от `_work/images/raw/` или сменете промпта и пуснете отново |

## 10. Съдържание и политики

Riot позволява фен видеа по League of Legends (вижте „Legal Jibber Jabber“ на сайта им), включително монетизирани, при условия, които е добре да прегледате. YouTube демонетизира масово произвеждано, повтарящо се съдържание („inauthentic content“), така че собствен ъгъл, редакторска намеса и качествен сценарий са важни и за приходите, не само за гледаемостта.
